# Windows 原生 EXE 发布设计（修订版 V2）

修订日期：2026-10-26。状态：设计方案，尚未实现或通过安装验收。本版替代首次提交的设计，落实代码评估中发现的启动绕过、复制失败、取消恢复和用户身份问题。

## 目标

交付可下载安装的 Windows 版本，按「先修复核心 → 原生界面 → 安装与发布 → 隔离环境验收」实施。PowerShell 继续承担检查、切换与修复，WPF 负责交互：

- 发布 `ClaudeSwitcher-<version>-windows-setup.exe`（Inno Setup 安装包）。
- 安装包内包含 `ClaudeSwitcher.exe`（.NET 10 LTS WPF，自包含目录发布）。对用户交付一个安装 EXE，程序内部允许携带 DLL 和运行时文件。
- 继续发布 `ClaudeSwitcher-<version>-windows.zip`，明确标为 PowerShell 脚本兼容包，不称为原生程序便携包。
- macOS 沿用现有 `.app`、`.dmg`、`.zip` 打包脚本，在 macOS runner 上构建，并按实际架构命名。
- 首版原生程序只交付 `win-x64`。Windows 11 x64 为主验收环境；Windows 10 22H2 x64 为单独的兼容性验收环境，只有通过对应测试才在发布说明中列为支持。

### 与上一版的主要变化

| 项目 | V2 决策 |
| --- | --- |
| 运行时 | 使用 .NET 10 LTS；构建环境和随包运行时一起维护 |

| 验收 | 加入干净虚拟机安装、升级、卸载、跨账号 UAC 和故障恢复 |

## 背景与现状

当前 `windows/` 只有 PowerShell 核心、PowerShell WPF 界面、安装脚本和保镖脚本，没有 C# 工程、安装包工程或 Windows CI 构建任务。现有 `install.ps1` 负责：

1. 探测代理客户端和出口国家。
2. 将核心脚本安装到 `%USERPROFILE%\.claude-switcher\`。
3. 写入 `PROXY_MODE`、`COUNTRY_TARGET`、`TZ_TARGET`、`PROXY_GROUP`。
4. 配置置顶规则、时区、IPv6、DNS 和保镖计划任务。
5. 创建桌面快捷方式。

现有 `SwitcherUI.ps1` 提供 14 项检查、账号 A/B 切换、一键修复界面。代码评估已用内存桩复现三项缺陷，未运行真实安装器或操作账号资料：

- 同账号启动分支调用 `Start-ClaudeApp`，没有调用安检。
- 归档的 `robocopy` 返回 8 时，仍记录成功；切换后续可能删除当前数据目录。
- 全部 STUN 探针无响应时，仍返回 `ok:UDP不出网,零暴露`。

因此，复用的是核心的职责与代码基础，而不是接受其现有失败处理。上述问题是原生发行版的发布阻断项，脚本兼容入口也必须使用修复后的核心。

## 方案比较

### 方案 A：修复 PowerShell 核心 + WPF + Inno Setup（采用）

- 优点：用户无需预装 .NET；安全规则只有一个实现；既有脚本入口也获得修复。
- 成本：核心修复、C# 工程与测试、受限管理员助手、安装包和跨平台发布任务。
- 风险控制：核心恢复测试通过后再接界面，虚拟机验收通过后才允许正式发布。

### 方案 B：仅把 PowerShell UI 包装成 EXE

- 优点：改动最少，开发快。
- 缺点：EXE 只是启动器，仍依赖 PowerShell；用户感知和可维护性没有真正提升；后续签名、安装和错误处理仍不完整。

### 方案 C：把所有核心逻辑迁移到 C#

- 优点：长期可以摆脱 PowerShell 依赖。
- 缺点：迁移面大，账号切换、代理探测、计划任务和系统配置风险高；与 macOS/Linux 核心继续分叉，不适合本次迭代。

**结论：采用方案 A。** 不迁移整套业务到 C#，也不以包装 EXE 代替核心修复。单文件主程序优化推迟，不影响首版安装 EXE 的交付。

## 架构

```text
Inno Setup（管理员：只安装程序与受保护的助手）
  └─ %ProgramFiles%\ClaudeSwitcher\
       ├─ ClaudeSwitcher.exe + 自包含运行时
       ├─ scripts\（核心与兼容界面的发行模板）
       └─ helpers\（固定功能的系统配置助手、保镖模板）

ClaudeSwitcher.exe（原始普通用户：首次配置与日常界面）
  ├─ powershell.exe → 该用户 .claude-switcher\claude-switch.ps1
  │    ├─ 当次安检、账号切换、可恢复事务
  │    └─ accounts\A、accounts\B（保留现有存档内容与结构）
  └─ 必要时请求 UAC → Program Files 内的受保护系统配置助手
       └─ 白名单系统操作、绑定目标用户 SID 的保镖任务
```

### 核心安全与恢复（必须先完成）

1. 核心命令自身校验账号只允许 `A`、`B`，对正常启动和同账号启动都执行当次安检，不能依赖界面检查或旧的 `last-check.txt`。
2. 切换开始前先检查；数据切换完成后、真正启动 Claude 前再次检查。国家必须与目标一致，取不到国家也拒绝启动；检查期间或复制期间代理失效不得继续启动。
3. STUN 全无响应、无效响应或探测错误都表示未验证，阻断启动；只有获得有效结果且与有效代理出口一致才通过。保镖检查须确认目标用户的任务正在运行并有有效存活证据，不能仅检查任务存在。
4. `warn` 只对「IP一致」「ASN属性」两项允许作为非阻断提示；显示黄色，不宣称全绿。其他项目的 `warn`、任意 `fail`、未知状态或缺项均阻断。最终 `canLaunch` 由核心按规则计算。
5. 核心持有按用户 SID 隔离的跨进程互斥锁，串行执行切换、修复和用户配置升级；原生 UI、脚本 UI、CLI 都走同一锁。UI 单例仅用于体验，不能替代核心锁。检查写入的状态使用原子替换，避免共享文件半写。
6. 账号切换流程为：获取锁 → 验证状态/安检 → 完全退出该用户的 Claude → 归档至临时目录 → 验证归档 → 准备并验证目标数据 → 提交切换 → 再次安检 → 启动。禁止先删除唯一完整副本。
7. 每次 `robocopy` 必须立即读取退出码，0–7 按成功范围处理，8 及以上失败；提交前还须验证复制的文件清单与完整性。备份成功后才允许替换正式数据，`current.txt` 在对应提交阶段原子更新。
8. 事务记录位于账号目录外，记录操作 ID、阶段及受限路径，不写凭据内容。临时副本放在对应目标的同卷目录；`accounts\A`、`accounts\B` 的内部结构不变。异常退出后先检测并恢复或报告待恢复，禁止覆盖可能是唯一副本的残留。
9. 提交前失败保留或恢复原账号；已提交但启动前安检失败则保留已确认完整的目标数据、拒绝启动，并准确报告当前账号。恢复无法确认完整时返回 `recoveryRequired`，锁住后续切换。

### 进程边界

- `ClaudeSwitcher.exe` 不读取、复制、移动或删除账号目录内容。
- 账号目录只由修复后的 `claude-switch.ps1` 操作。
- EXE 只允许调用以下命令：
  - `checkdetail`
  - `status`
  - `fix`
  - `switch A`
  - `switch B`
- `switch` 的目标在 UI 层和客户端层都必须限制为 `A` 或 `B`，不能把用户输入拼进命令。
- 使用系统目录中明确定位的 Windows PowerShell 5.1，通过 `ProcessStartInfo.ArgumentList` 传递参数，启用 `-NoProfile -NonInteractive -ExecutionPolicy Bypass -File`；不经过 `cmd.exe`，不拼接动态 PowerShell 代码。
- 异步读取 UTF-8 stdout/stderr，限制输出大小，避免阻塞 UI 或管道死锁。捕获内容先脱敏，再进入日志与错误详情。
- `status` 等待上限 10 秒；独立 `checkdetail` 为 90 秒，内部网络探测也要有有限超时。超时可终止对应查询进程，不得使用旧结果补齐。
- `switch` 等待 120 秒后显示「仍在处理」，继续按操作 ID 观察状态，不直接杀整个进程树。归档与载入阶段各有 10 分钟上限；超限或取消时先停止该复制子进程并确认退出，再恢复或标记待恢复。进入提交阶段后延迟取消直至安全点。
- `fix` 等待 180 秒后显示实际阶段。UAC 取消返回明确结果；管理员助手执行有界步骤，不因 UI 超时而被任意强杀。
- UI 关闭不能中断正在提交的切换；再次打开能从核心状态识别运行中或待恢复操作。

### 输出协议与兼容

原生 UI 使用新增的 `-Json` 模式，每次返回一个有版本的 JSON 结果；现有文本命令仍保留：

```text
<检查项>=<ok|warn|fail>:<详情>
```

- 结果包含 `schemaVersion`、`operationId`、`command`、`success`、`code`、`message`；检查结果另含 `checks` 和 `canLaunch`，切换结果另含 `current`、`phase`、`recoveryRequired`。
- UI 生成操作 ID 并传入核心；返回 ID、命令和协议版本必须匹配。stdout 只输出协议结果，普通日志另行处理，不把旧的缓存文件当作本次结果。
- 14 项检查使用稳定 ID 与显示名称，每项包含 `status`、`blocking`、脱敏 `detail`；允许 `ok/warn/fail/unknown`，`unknown` 必须阻断。旧文本模式把未知结果映射成 `fail`，避免旧界面误判。
- 解析器校验唯一性、全部必需项、状态枚举及阻断规则；缺失、重复、未知检查 ID、格式错误或 `canLaunch` 与检查内容矛盾时拒绝结果。
- 操作失败返回非零退出码；复制工具的 0–7 仅在核心内部归一化，不能直接当成 UI 命令的退出码。
- 进程退出码、结果字段必须同时表示成功，UI 才报告完成。空输出、错误协议、取消和仅有日志都不能视作成功。
- 新 UI 遇到旧核心或缺少协议能力时提示重新配置/安装，不能降级为不受保护的启动；兼容脚本界面也须修正其成功和警告判定。

## 用户界面

首版保持现有 Windows 版信息架构：

- 顶部：标题、环境状态徽标。
- 中部：14 项检查列表，显示名称、详情、状态图标。
- 账号区：当前账号、账号 A、账号 B。
- 操作区：重新检查、一键修复。
- 失败提示：显示可操作错误，不显示敏感 IP 或代理凭据。

行为：

- 启动后自动执行 `checkdetail`。
- 同一操作期间禁用冲突按钮，展示当前阶段；失败或取消后按核心返回状态恢复按钮，待恢复状态只允许恢复操作。
- 检查失败时禁用账号启动按钮；即使绕过 UI，核心仍须拒绝启动。
- 账号切换成功后刷新状态和检查；待恢复时显示恢复说明，不显示成功。
- 修复完成后重新检查。
- 核心脚本缺失时显示安装/重新安装提示，不自动创建或下载脚本。
- 退出时只退出界面，不主动结束 Claude；未完成事务按上述安全点处理。
- 首次进入配置向导：选择/确认代理模式、代理组、检测到的地区目标，展示将执行的系统变更；配置未完成前不允许启动 Claude。

## 安装与打包

### 原生程序

- 目标框架：`net10.0-windows`；使用 .NET 10 LTS。
- 发布配置：`win-x64`、`SelfContained=true`、`PublishSingleFile=false`。首版不启用裁剪或 Native AOT；完整发布目录交给安装器打包。
- 构建 SDK 用 `global.json` 锁定审核过的版本，CI 与本地保持一致；依赖版本与恢复输入一起纳入版本管理。
- 发布目录只包含运行所需文件；图标嵌入程序资源，安装包包含必要许可说明。
- 不要求用户安装 .NET Runtime。
- 截至 2026-10-26，.NET 8 支持在 2026-11-10 结束，.NET 10 LTS 支持至 2028-11-14。自包含运行时不会因用户更新系统 .NET 自动替换；每次发布检查运行时补丁，安全补丁通过新版本安装包交付。

### Inno Setup

- 安装包名称：`ClaudeSwitcher-<version>-windows-setup.exe`。
- 安装器提权后只把程序、发行模板和固定功能助手安装到受保护的 Program Files 目录，建立原生 EXE 快捷方式。此阶段不使用提权账号的 `USERPROFILE/APPDATA` 初始化用户数据。
- 安装完成后通过原始用户身份启动配置向导；不能取得原始身份或用户从提升后的终端启动安装器时，只完成程序安装，提示用户从自己的普通桌面会话打开程序配置，不猜测目标用户。
- 原用户向导探测代理、确认地区、建立该用户配置与脚本副本；然后按需调用受保护的系统助手请求 UAC。首次安装程序和首次系统配置可能各出现一次授权，日常检查/切换不提权。
- 助手只接受固定动作和经过类型/枚举校验的参数，SID 需与发起配置的实际 Windows 交互会话核对，路径由 Windows 身份与安装位置派生；不执行传入命令、用户可写脚本、任意文件路径或可执行配置。
- 保镖任务绑定目标用户 SID 与该用户登录触发器，使用普通用户权限，指向受保护的保镖脚本；仅处理该用户的 Claude。旧 `ClaudeBodyguard` 任务先核实归属再迁移，不能覆盖其他用户任务。日常状态检查同时兼容可确认归属的旧任务。
- 用户配置存为独立的版本化 JSON；旧版脚本中的四个配置值通过静态解析迁移，不能执行旧脚本来读取配置。升级不重置已确认的地区、代理模式或账号状态。
- 系统变更前记录时区、将修改的 IPv6 绑定及本项目管理的代理规则；只改本项目管理块，保留其他代理规则。未知国家、CN 出口、未知时区映射或冲突的系统地区配置，均在变更前失败，不用 US/美国东部或环境变量 `FORCE` 静默兜底。
- 只有系统助手确认成功、用户初始化成功后才标记「配置完成」。UAC 取消或部分失败显示实际阶段，允许安全重试；不自动启动 Claude。
- 卸载先停止并移除本安装管理的保镖任务，再移除程序和快捷方式；默认保留各用户账号与恢复资料。系统设置恢复为明确选项，只在有有效备份且当前值仍是本项目写入值时恢复，避免覆盖用户后续修改；不直接调用原用户执行 API 完成卸载清理。
- 安装、升级和卸载不能与切换事务并发；发现运行中/待恢复事务时先停止变更并报告状态。多用户安装按已登记的 SID 检查，不把某个用户的锁当作整机锁。

### `install.ps1` 非交互参数

`install.ps1` 保留脚本兼容安装入口，分离用户初始化与白名单系统配置，新增：

- `-NonInteractive`：所有路径都不读取控制台、不 `pause`；缺少必要信息时返回字段名与非零退出码。
- `-ProxyMode <auto|clash-verge|sing-box|clashx|surge|wireguard|other>`：允许显式选择，未传时尝试探测；探测失败不得静默选 `auto`。
- `-ProxyGroup <string>`：Clash Verge 探测失败时必须传入并验证；不盲目使用 `GLOBAL`，配置值按数据序列化，不能插入为可执行 PowerShell 代码。
- 用户初始化以脚本自身发行目录为源，程序安装向导从受保护发行模板调用；取消上一版的通用 `-CoreSource` 与没有实际行为的 `-SkipLaunch`。

默认交互模式允许询问缺少的信息。脚本兼容安装与原生向导复用相同的配置校验和系统助手；非交互缺参失败必须发生在写配置或修改系统之前。

## 构建与 CI

### 新增脚本

- `scripts/package-windows.ps1`：
  - 校验发行版本及 Windows 数字文件版本的映射，拒绝非法输入。
  - 检查固定 SDK/Inno Setup 工具版本，运行 PowerShell 与 .NET 测试。
  - 发布自包含目录 `win-x64`，按明确文件清单收集程序与脚本，不混入 `bin/obj`、测试资料或账号数据。
  - 调用 Inno Setup 编译安装包。
  - 将产物写入 `build/`，并检查关键文件存在。
- 保留 `scripts/package-macos.sh` 不变。

### GitHub Actions

```text
build-macos-linux ───────┐
                        ├─ verify-and-publish → 正式 GitHub Release
build-windows → vm-smoke ┘
```

- `build-macos-linux`：在 macOS runner 运行既有检查和打包，产出 macOS app/dmg/zip、安装套件和 Linux 脚本包。版本与架构从构建结果传递，不将架构写死为 arm64。
- `build-windows`：在固定 Windows runner 镜像上使用锁定的 .NET 10 SDK 和 Inno Setup，执行隔离测试，生成 Setup EXE 和明确文件清单的脚本兼容 zip。PR/主分支 checks 也运行 Windows 测试与构建。
- 两个构建任务只上传命名唯一的 CI artifacts，不能各自创建或修改正式 Release。Windows 脚本 zip 只由 Windows 任务生成，避免两处争写。
- `vm-smoke`：在可重置的专用 Windows VM/测试 runner 验证实际安装流程；没有 VM 验收记录时只保留构建工件或草稿 Release。测试机与维护者日常环境隔离，不用托管 runner 冒充干净 Windows 10/11 无运行时环境。
- `verify-and-publish` 使用 `needs` 等待两个平台构建和 VM 验收成功，下载同一次运行、同一提交的工件，核对版本/架构/完整清单，生成覆盖所有最终文件的 `SHA256SUMS-release.txt`。
- 先上传到草稿 Release，确认资产与校验和完整后才转为正式发布；任一任务失败或产物缺失不发布。正式版本不可用 `--clobber` 静默换包；修复使用新版本。
- 构建任务只需仓库读权限，最终发布任务才授予 `contents: write`；按 tag 限制并发发布。工具不可用时明确失败，不能跳过 Windows 安装包。

## 安全与失败策略

- 安检可在内存读取必要的出口 IP 并完成比较，但 UI、日志、测试报告、构建工件不得暴露原始 IP、Cookie、账号凭据或代理密钥；这是对旧版「不读取 IP」矛盾表述的修正。
- 不在检查不完整时显示“环境安全”。
- 不把 PowerShell 的 stderr 静默当作成功；记录可读错误摘要，但不回显敏感信息。
- 核心补齐并统一执行地区/代理/账号检查，不能依赖界面或直接调用旧的不受保护分支。
- 不把 `switch` 参数直接交给 shell 字符串拼接。
- 维护者工作机只改仓库、运行隔离测试与编译；真实安装/卸载、计划任务和网络设置变更只能在专用测试 VM 中进行。不得为验收部署维护者本机。
- 首版没有签名证书时发布说明如实标为未签名 Beta，不能承诺消除 SmartScreen 提示；有证书时只对最终签名产物生成发行校验和。

## 测试策略

### PowerShell 核心回归（先写失败测试）

测试使用临时用户根目录、假网络/进程/复制工具及合成数据，不访问真实账号、住宅 IP 或系统配置：

1. 同账号启动、首次初始化和 A/B 切换都在启动前执行当次安检；国家不同、取不到国家或代理中断时启动调用为零。
2. STUN 无响应/无效响应阻断；有效结果与代理出口不一致阻断。
3. 缺项、重复项、未知状态阻断；只有两项明确白名单警告允许非绿色的可启动状态。
4. `robocopy` 的 0–7/8+ 边界、归档失败、载入失败、磁盘满、文件被占用，均不删除唯一完整副本或错误推进账号标记。
5. 在归档、准备、提交、启动前每个阶段注入异常或终止，下一次进入能恢复或明确进入待恢复状态；不能覆盖恢复残留。
6. 两个进程竞争切换/修复时仅一个进入写操作；旧脚本 UI 与原生 UI 使用同一个核心锁。
7. UAC 取消、助手失败不输出修复成功；非交互缺参不等待输入，也不修改系统。

### C# 单元与进程集成测试

至少覆盖：

1. 合法的 14 项协议结果全部解析成功，操作 ID、命令和版本相符。
2. `warn` 不产生全绿状态。
3. `fail` 阻断。
4. 缺少检查项导致不完整/失败。
5. 重复项导致失败。
6. 未知项导致失败。
7. 格式错误的行导致失败。
8. 进程退出码非零导致失败。
9. 查询超时终止查询；切换软超时、取消、关闭 UI 不强杀提交，重新打开能看到正确阶段。
10. `switch` 只接受 `A`/`B`，拒绝其他目标。
11. 命令参数通过参数列表传递，不拼接到单个字符串。
12. 核心脚本不存在时返回可操作的安装错误。
13. stderr 与检查详情包含合成 IP/凭据样例时，界面和日志只出现脱敏内容。
14. stdout/stderr 并发大输出、中文路径和中文状态均正确处理，不阻塞 UI；旧协议核心被拒绝。

## 验收标准

1. 同账号、脚本直调与原生 UI 均不能绕过核心安检；STUN 未验证、地区不符、状态不完整时不启动 Claude。
2. 归档/载入失败、取消、异常退出和并发操作不丢唯一完整副本；恢复状态明确且可重复验证。
3. .NET 10 WPF 测试、PowerShell 隔离回归、`win-x64` 自包含发布与 Inno Setup 编译均成功。
4. 无需预装 .NET 的验收 VM 能运行原生 EXE；快捷方式、首次配置、升级和卸载通过矩阵验收。
5. 用户配置、账号资料和任务绑定原始用户；系统助手只执行受限动作，普通启动和 Claude 进程不提权。
6. UI 不以空输出、日志、旧缓存、协议矛盾或部分失败显示成功；警告、进行中、待恢复均有明确状态。
7. Release 由一个汇总任务发布，包含 Windows Setup、脚本兼容包、既有其他平台产物及覆盖全部文件的最终校验和。
8. 现有 macOS/Linux 回归按对应平台验证；维护者本机已安装版本、账号和系统设置不被修改。
