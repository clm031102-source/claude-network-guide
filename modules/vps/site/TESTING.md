# 新手实测规程

> 独立源码参考：下文保留上游测试规程与历史记录，不代表本次整合已执行同样验收。当前没有公开教程站；先按 README 启动本地预览，再根据实际环境开展测试。

网站的目标是「第一次接触的人，只看网站、不问人，就能配好」。这一条只能靠真人测试来验证。每次大改以后，按这份规程找 1 到 2 个人测一遍。

## 找什么样的人

- 没有自己配过服务器、没有用过 Clash 之类客户端的人；
- 会用电脑上网、会复制粘贴就行；
- Windows 和 Mac 各找一个最好（两边的步骤不一样）。

## 准备

- 一台**全新的**服务器（按第 1 步买，或者在商家后台重装成 Ubuntu 24.04）。不要用正在用的服务器测试。
- 测试者自己的电脑和手机。
- 一个计时器、一张记录表（见下）。

## 给测试者的任务（原话念给他听，不多解释）

> 打开本机预览地址 http://127.0.0.1:4410，从第 0 步开始，按网站说的做。检查手机和电脑的实际出口与连接；第三方网页评分仅作辅助记录，不作为平台认可或账号安全的证明。
> 遇到问题先自己在网站上找答案。实在做不下去了再叫我。

## 观察者的规矩

- **只看不说**：不提示、不指路。测试者问你，你就回答「你觉得网站上哪里会写这个？」
- 测试者说「我卡住了」并且 5 分钟没有进展，才可以帮忙；帮之前先记下卡在哪里、他在找什么。
- 每一步记下用时。
- 密码由测试者自己输入，观察者不要看、不要记。

## 已做过的走查记录

### 2026-10-16：维护者按新手视角走查（不是真人测试）

把主线 0–5 步按新手的视角逐句过了一遍，发现并修复：

1. 手动路线中途关掉终端，会丢失所在目录和 `R=…` 变量，后面的命令全部失败 → 第 3 步加了「全程用同一个终端窗口」的提示和恢复办法。
2. 登录信息是 `.md` 文件，新手不知道用什么打开 → 第 3 步说明用「文本编辑」或「记事本」打开、订阅地址要整行复制。
3. Claude Code 让用户输入以 `!` 开头的命令来输密码，新手不理解 → 第 3 步解释了 `!` 的含义和操作方法。
4. 读者卡住时没有反馈渠道 → 每一步、每篇 How-to 末尾加了预填模板的 GitHub 反馈链接。
5. 右侧目录把两个标签页（AI / 手动）的小标题混在一起 → 目录只列二级标题。

### 2026-10-16：照做验证（容器端到端，不是真人测试）

目的：验证「照着网站上的命令做，能否完成部署」。做法：本机起两个一次性容器——一个扮演刚买来的 Ubuntu 24.04 服务器（地址就是教程里的示例 `203.0.113.10`，root 密码登录），一个扮演新手的电脑。命令**直接从本地预览页面** http://127.0.0.1:4410/guide/3-deploy/「自己照着敲」里提取，只把「你的IP」换成 `203.0.113.10`，在同一个终端会话里依次执行，密码由模拟终端输入。

结果：

| 网站上的步骤 | 结果 |
|---|---|
| 下载方案（git clone） | ✓ |
| 建立免密登录（connect.sh，输入一次 root 密码） | ✓ 显示「完成：以后用 ssh bwg 登录」 |
| upload / init / base / cert / xui / sub / cliproxy / maint | ✓ 每段都显示「xxx 完成」（测试机是 arm64，顺带覆盖了 ARM 安装包） |
| verify --full | 33/34 通过；唯一 FAIL 是「证书续期演练」——测试环境用自建 CA 证书，无法向 Let's Encrypt 续期，真实服务器上这一项通过 |
| save --lang zh | ✓ 生成「Claude 网络指南-bwg-登录信息.md」，没有桌面目录时放在主目录（与网站对 WSL 的说明一致） |
| 第 4 步：用登录信息里的 Clash 订阅启动客户端（mihomo，Clash Verge Rev 的内核） | ✓ 两个节点都能上网；Google 走代理、百度直连、chatgpt.com 分到 AI 组；两个节点的 UDP 都通 |

测试环境特有、真实环境不会遇到的三处（都不是网站或脚本的问题）：

1. 容器申请不到 Let's Encrypt 证书，预置了自建 CA 签的证书（`cert` 阶段检测到有效证书会跳过申请）。
2. 预置 CA 时测试者的操作失误（服务器没信任这张 CA），导致 xui 阶段停在「面板没有在 HTTPS 53998 上响应」；按网站写的「修好原因、重新运行同一段」，从 xui 接着跑就通过了——顺带验证了「出错后重跑同一段」这条说明是对的。
3. 本机网络的 DNS 是代理软件的 fake-ip，容器里的「服务器」解析到 198.18.x.x 导致 TCP 不通；在测试服务器 hosts 里写真实地址后正常。

结论：网站上的手动路线命令原样可用，「你应该看到」的提示与实际输出一致。
