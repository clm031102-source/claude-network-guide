# 两套上游项目的核心逻辑与本项目改造

[目录](tutorial.md) · [来源声明](../NOTICE.md) · [逐文件来源清单](../UPSTREAM.json)

两个源项目解决的是不同层次的问题：VPS 模块把远程网络服务搭起来；切换器模块审计本机环境，并提供账号快照和启动约束。本项目把学习和使用顺序重排为：**购买 VPS → 本人购买固定独享住宅 IP → 验证最终出口 → 检测 → 启动**。

“完整引入”指固定 commit 的全部已跟踪文件已收入模块，保留原始路径和摘要映射；不包含原作者 Git 历史、未提交文件、私有机器或账号数据。品牌、教程入口和可复制提示词使用本仓库，许可证和出处继续保留原作者信息。

## VPS 模块：分阶段部署、分层转发、可恢复维护

| 能力 | 核心逻辑 | 本项目位置 / 处理 |
|---|---|---|
| 本地 SSH 准备 | 每机器独立密钥、别名、配置备份，验证免密后再加固 | `modules/vps/skills/claude-network-guide/scripts/local/connect.sh` |
| 远程阶段执行 | 上传脚本，逐阶段执行，输出私有交付文件 | 同目录 `scripts/local/remote.sh` |
| 初始化 | 检查系统 / IP / 已有部署，生成独立凭据和状态 | `scripts/server/xxd-vps.py` 的 `init` |
| 系统基础 | apt 依赖、BBR / fq、UFW、SSH 有效配置检查、服务器时间 | `base`；限定目标 VPS，不修改本机 |
| 证书 | ACME IP 短期证书、Nginx 挑战、续期服务和钩子 | `cert`；必须检查持续续期 |
| 双入口 | REALITY 443 与 TLS 2443，REALITY 本机回落与兼容参数 | `xui`、`files/xray-template.json` |
| 客户端身份 | Mihomo / OpenClash 与 Shadowrocket 独立身份、flow 差异 | `xui`；一个身份可单独撤销 |
| 订阅代理 | 本地白名单路径，HTTPS 前端，订阅及月流量展示 | `sub`、`files/sub-proxy.py` |
| 规则镜像 | 从公开上游取规则，转换 / 核对格式，失败保留旧版 | `files/xxd-vps-refresh-rules`、`rule-sources.json` |
| 分流模板 | AI 规则优先，国内 / 常用应用分类，ASN 与规则数据镜像 | `files/clash-template.yaml`、`files/rules/` |
| DNS 方案 | fake-IP、按域名选择解析器、DNS 尊重路由，减少额外解析 | 模板保留；另做实际上游验收 |
| 流量校准 | 网卡计数、方向、重置日、商家读数校准，可选 KiwiVM | `traffic` / `kiwivm` 子命令 |
| API 服务 | 独立用户、本地监听、HTTPS 前置、分离管理 / 调用 Key | `cliproxy`；移到独立高级流程 |
| API 自动更新 | 校验、等待空闲、备份、原子替换、健康检查、回滚 | `files/cliproxy-auto-update`；不是网络默认依赖 |
| 维护 | 证书、规则、备份与可选 API 更新的定时器 | 纯网络按[维护章](maintenance.md)分开设置 |
| 验收 / 导出 | 服务、端口、TLS、订阅、规则、SSH、备份与完整栈状态 | `verify` / `export`；完整模块仍含 API 前提 |
| 配置备份 | SQLite 一致性快照、配置归档、限制权限、保留最近 7 份 | `backup`；异地加密副本另行选择 |
| 教程网站 | Astro 网站、中文 / 英文主教程、How-to、FAQ、名词表及素材 | `modules/vps/site/` 全部保留 |
| 多语言与协作 | 多语言 README、交付标签、设计 / 排障资料、CI 与发布资料 | 模块内原文件按映射保留 |

**新增的关键一层是住宅出站。** 原模块默认从 VPS 自身出站；结构 B 需要显式添加另购住宅出站，并将两条入站绑定它。部署器安装成功不会自动完成这一步。

模块保留 `xxd-vps` 等运行时兼容名称，避免修改现存服务、备份和升级路径。用户教程与提示词使用 `claude-network-guide`；兼容名称不要求用户访问另一个仓库。

## 切换器模块：审计门禁、快照隔离与运行时防护

| 能力 | 原始设计 | 本项目的采用方式 |
|---|---|---|
| 启动前审计 | 代理、TUN、出口、IP 历史、时区、地区、IPv6、DNS、STUN、守护、规则、语言、ASN、可达性 | 保留原模块；新工作台采用独立、证据驱动的检查集 |
| STUN 探针 | Python 标准库构造 Binding 请求并解析映射地址 | 新内核也做有限 STUN 样本；无回包不视为通过 |
| 进程保镖 | 周期检查代理与网卡，故障时关闭受保护进程 | 保留高级模块；新工作台不安装，也不声称零泄漏 |
| 配置漂移修复 | 周期检测并恢复预设配置 | 高级模块保留；新默认流程不改本机设置 |
| 置顶路由 | 在客户端规则前加入域名 / 端口策略，核对运行时接口 | 保留模块；新工作台暂不读取代理控制接口或自动改规则 |
| 快照切换 A–D | 当前目录归档，目标快照载入；同卷 rename / COW 克隆与回退 | 全部保留，必须独立选择；新工作台不读写登录态 |
| 跨账号保留 | 白名单小文件暂存与恢复，拒绝越界 / 符号链接 | 保留可选能力，默认不启用 |
| 加密导入导出 | macOS `hdiutil` 加密镜像、格式校验、拒绝覆盖已有槽位 | 保留；不代表本地会话能恢复服务端授权 |
| macOS 原生 GUI | SwiftUI 界面、菜单栏、账号卡片、更新信息 | `modules/switcher/app/` |
| Windows / Linux | WPF 或 shell / systemd 适配、平台安装器和守护 | `modules/switcher/windows/`、`linux/`，保留 Beta 边界 |
| 更新 / 回滚 | 文件校验、自检、失败恢复，按平台提供更新路径 | 模块保留；发布打包要以本项目路径重新验证 |
| 地区 / 客户端选择 | 探测地区和代理客户端，修改对应配置 | 保留模块但不是新工作台默认动作 |
| 临时浏览器 | 隔离 profile、受限协议、结束清理 | `open-safe`；独立使用与验收 |
| CLI 体检 | PATH、真实路径、版本、安装来源、重复安装 | `cli-info`；只读工具 |
| 显式代理诊断 | 只用明确指定代理请求固定官方目标，不回退直连 | `diagnose-proxy`；新工作台继承这一输入原则 |
| 设备信息 | 字体、GPU、虚拟环境；浏览器侧 Canvas / WebGL 展示 | 作为参考保留，不用作平台风险推断 |
| Web 检测 | 浏览器出口、区域、WebRTC、IPv6、近似 DNS 和指纹展示 | `modules/switcher/docs/`；不替代桌面或网络层验收 |
| 测试 / 设计 / 工具 | shell / Python / Swift 静态与隔离测试、设计稿、发布脚本、资源 | 完整保留，历史通过不等于当前全平台实测 |

上游关于平台风控的推测、历史“战绩”、成功率、邀请推广与语言 / 字体风险断言不构成本项目结论。默认流程检查可观察的网络行为，不试图推断未公开的风控规则。

## 新 UI 和内核具体改了什么

| 部分 | 改造结果 |
|---|---|
| 导航 | VPS 购买、住宅 IP、网络配置、检测与设置按顺序组织 |
| 状态 | `pass / warning / fail / unknown` 分开；未检测时不显示伪造绿色结果 |
| 证据 | 每项给出检测范围、观察结果、后续动作与是否阻止启动 |
| 代理 | 自动识别本机系统/客户端入口并显示来源；高级设置可覆盖，实际请求验证候选 |
| 自动发现 | 读取本机系统代理、已知客户端/端口、网卡/路由/DNS和Claude安装证据；空字段不成为失败 |
| 出口 | 显式代理与系统默认 TCP 各用两个服务交叉核对；预期IP可选，未填写时报告实测一致性 |
| 并发与超时 | 有整体时间预算，失败保持未知；检测、保存和启动避免状态混用 |
| 门禁 | 关键证据缺失阻止启动；每次启动重新检测并校验官方客户端 |
| 数据最小化 | 不读账号，报告默认仅在内存，导出脱敏；只存本机配置 |
| 本地服务 | 回环监听、会话令牌、来源与请求校验、本地静态资源 |
| 系统影响 | 不自动改时区、语言、DNS、IPv6、防火墙；没有静默常驻守护 |

Windows 主入口现为无需 Python 的便携程序：独立窗口打开后自动执行一次只读体检。它与源码界面使用同一检测内核，旧原生模块仍完整保留；守护、账号快照和自动修复没有偷偷并入体检流程。

## 明确保留的限制

新工作台还没有完整上游 DNS 泄漏测试、完整浏览器 WebRTC 审计、防火墙级持续阻断、所有客户端的运行时规则验证或平台账号状态验证。IPv6 / UDP 无响应保持未知；默认允许启动的报告仍可能含这些非关键未知项。

实际线路、住宅采购、服务端部署、跨平台安装和每种故障恢复需要你自己的环境实测。详细标准见[验收章](validation.md)，不得用单元测试或界面截图代替。
