# 04 · 启动前检测工作台

[目录](tutorial.md) · [上一章](03-network-setup.md) · [下一章：逐项验收](validation.md)

新工作台的界面名称是 **Claude 网络指南**。它先展示你的配置和检查证据，再决定是否能通过本界面启动已经安装的官方 Claude。它不会替你购买线路或自动修复系统。

## 1. 打开工作台

安装 Python 3.10 或更新版本后，在本仓库目录运行：

Windows：双击根目录的 `启动检测.cmd`，或运行 `py -3 -m app.server`。

macOS / Linux：运行 `bash start.sh`，或 `python3 -m app.server`。

按终端给出的本地地址打开页面，优先使用 `http://127.0.0.1:8765`，被占用时依次尝试至 `8774`。明确传入 `--port` 时只尝试指定端口，失败会退出，不结束已有进程。保留服务终端；关闭它即停止工作台。页面仅向本机服务请求数据，不在后台自动检测网络。

Linux 可以使用检测界面，本版本不提供绕过客户端校验的 Linux 启动功能。桌面版模块的兼容情况与新工作台的检测能力分别看待。

## 2. 填写连接设置

| 字段 | 填什么 |
|---|---|
| 预期住宅 IPv4 | 本人购买的最终公网住宅 IPv4，不是 VPS 中转 IP；不填域名、IPv6、内网或保留地址 |
| 本地 HTTP 代理 | 你实际使用的 HTTP / mixed 监听地址，例如 `http://127.0.0.1:7897`；端口以你的客户端为准 |
| Claude 路径 | 已安装官方客户端的本机路径；Windows 对应 Claude.exe，macOS 对应标准位置的 Claude.app |
| 自行购买住宅 IP | 确实已完成本人采购与核验再勾选；它是一项声明，不是程序验证结果 |
| 要求 TUN 证据 | 默认开启；程序同时寻找已知代理进程和活动 TUN / VPN 网卡 |
| 要求 UDP 证据 | 默认关闭；开启后，没有可比较的 UDP 样本也会阻止通过工作台启动 |

当前代理字段只接受**无账号密码的 HTTP URL**。上游住宅代理需要认证时，凭据放在你自己的代理客户端中，让它在本机提供无凭据且仅本机可用的入口。不要在 URL 中填住宅用户名、密码，也不要使用公网无认证监听。

点击“保存设置”。更改配置会清空旧检测报告，必须重新检测。

## 3. 运行检测并理解四种状态

点击“运行启动前检测”。后续需要复测时点击“重新运行检测”。整体探测有时间预算；超时和缺证据不会伪装成成功。

| 状态 | 意义 |
|---|---|
| 已通过 `pass` | 这项有限范围的测试取得预期证据 |
| 需留意 `warning` | 信息性提醒或人工声明，需要结合场景判断 |
| 未通过 `fail` | 观察到与配置要求冲突的结果 |
| 未验证 `unknown` | 没有足够证据、目标无响应或当前实现不覆盖该问题 |

**“允许启动”不等于“每项都已通过”，更不等于“没有泄漏”。** 当前门禁只要求关键项通过；部分边界项会继续显示未验证。

## 4. 实际检测范围

| 检查项 | 当前实现 | 对启动的影响 |
|---|---|---|
| 自行采购声明 | 读取你的确认，不认证独享 / 住宅 / 合法来源 | 没有确认会阻止启动；已确认仍显示提醒 |
| 显式代理出口 | Cloudflare trace 与 ipify 两个 HTTPS 服务，明确走填写的 HTTP CONNECT 代理 | 两个结果都须等于预期住宅 IPv4；缺失、冲突会阻止 |
| 系统默认 TCP 出口 | 不读取 HTTP 代理环境变量，用系统默认路由访问两个 HTTPS 服务 | 同样须等于预期住宅 IPv4；缺失、冲突会阻止 |
| TUN 进程与网卡 | 本机进程和活动接口的启发式证据 | 默认要求；自定义客户端可能识别不到，显示未验证 |
| Claude 生态传输 | 对 `claude.ai`、`api.anthropic.com`、`s-cdn.anthropic.com`，经显式代理和默认通道建立 TLS 连接并验证证书与主机名 | 关键传输证据不完整会阻止；不读取 HTTP 响应，不证明登录 / 账号可用 |
| DNS | 本地 A 记录样本与 fake-IP 观察 | 上游 DNS 路径始终明确标为未验证，不据此放行或判安全 |
| UDP / STUN | Cloudflare / Google 两个 STUN 目标均返回匹配样本才通过；仍只是有限 UDP 样本 | 观察到不同出口始终阻止；只有部分或没有样本默认未验证，启用要求 UDP 后阻止 |
| IPv6 | 通过默认通道访问独立 IPv6 查询目标 | 观察到额外 IPv6 出口会阻止；超时保持未验证，默认不阻止 |
| ASN / 归属 | 查询 ipinfo 的网络归属参考 | 不认证住宅、独享或信誉；若该查询明确观察到不同于预期的出口，会阻止启动；查询失败仍为未验证 |
| 时区 / 语言 | 只显示本机信息及边界提示 | 不把中文语言或时区不同直接视为危险，不修改设置 |
| Claude 文件 | Windows 验证有效的 Anthropic Authenticode；macOS 检查标准路径、签名与应用标识 | 缺失或无法验证会阻止；不接受任意可执行命令 |

默认通道与代理通道使用相同出口服务，只证明这些样本的路径。在规则模式下，目标域名可能走不同分组。启动后仍需在代理内核连接列表核对 Claude 的实际连接，方法见[验收章](validation.md)。

IPv6 / UDP 无响应可能来自服务、DNS、网络故障或阻断，不会被写成“安全”。DNS 上游、完整浏览器 WebRTC、网络层断线阻断尚未由本工作台完整验证。

## 5. 启动 Claude

关键检查通过后，使用“启动 Claude”。服务器会**重新运行检查**并重新核对客户端，不能只依赖页面上一次显示的通过结果。期间配置与重复操作被限制，防止拿旧结果启动。

只启动已经安装且能验证的官方程序，不自动下载，不登录，不切换账号，不读取 Cookie 或 OAuth 文件。已经运行的 Claude 不受此门禁控制。

工作台没有常驻保镖：启动后代理掉线，它不会自动杀进程或改防火墙。更换节点、关闭 TUN 或改变网络前，保存工作并退出 Claude；之后重新检测。需要持续阻断时另行配置网络层策略并做故障演练。

## 6. 保存位置与导出

本机设置保存到：

- Windows：`%LOCALAPPDATA%/claude-network-guide/config.json`
- macOS / Linux：`~/.config/claude-network-guide/config.json`

配置包含你填写的 IP、代理入口、客户端路径和开关。不要把它提交到公开仓库。正常检测报告保存在进程内存中，不自动上传或保存历史。

“导出报告”下载脱敏 JSON，供自己排障或提交 Issue；程序移除配置路径并遮盖地址，但截图、手工补充和第三方错误文本仍需你自己检查。导出报告不包含账号登录态。

## 7. 会访问哪些外部服务

点击检测或启动时，后端会按实际实现访问 Cloudflare、ipify、ipinfo、STUN 服务，以及上表的 Anthropic 固定目标；这些服务能看到到达它们的请求源地址。**如果你的路由有旁路，检测本身可能让测试服务看到实际直连地址。** 这是测量默认路径的必要含义，测试请求不携带 Claude 账号凭据。

本项目没有中央报告服务器，没有把检测结果提交给仓库维护者。详细本地服务保护见 [SECURITY.md](../SECURITY.md)。
