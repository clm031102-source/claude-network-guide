# 05 · 验收：每个结论都对应一次实际测试

[目录](tutorial.md) · [检测说明](04-preflight-check.md) · [日常维护](maintenance.md)

服务器部署完成、本地检测通过、Claude 能打开、账号可使用是不同结果。验收记录分别写，不用一个总分代替。

## 服务器侧

以下命令在你自己明确选定的 VPS 上执行。它们主要读取状态；证书续期演练会联系 ACME 测试服务并可能运行重载钩子，安排在可接受维护的时间。

```bash
systemctl is-active x-ui nginx xxd-vps-sub
systemctl is-active xxd-vps-cert-renew.timer
ss -Hlnt
sshd -T
ufw status verbose
nginx -t
systemctl list-timers --all
```

| 检查 | 通过所需证据 |
|---|---|
| SSH | 新终端密钥登录成功；`sshd -T` 显示密码和键盘交互认证关闭；救援入口可用 |
| 服务 | x-ui、Nginx、订阅服务正在运行，重启后能恢复 |
| 监听 | 内部订阅 / API / 回落端口只监听回环；公网端口符合本次用途 |
| 防火墙 | SSH 未被误封；网络方案没有开放 API 8318；管理面板来源受限 |
| 证书 | 证书包含实际服务器 IP、链可信、未过期；续期定时器和演练成功 |
| 订阅 | 两种格式都可读取，含两个真实入口；未知路径不返回订阅；不在日志记录凭据 |
| 规则 | 下载失败时保留旧版；声明的格式与实际内容相符；内核加载没有错误 |
| 备份 | 至少有一份权限受限的有效备份，已确认内容覆盖当前修改 |

内部服务名中的 `xxd-vps` 是保留的兼容标识，见[来源声明](../NOTICE.md)。不要为了界面命名直接批量改已运行的服务名。

## 客户端与实际出口

| 维度 | 怎么测 | 不能怎样推断 |
|---|---|---|
| 显式代理 TCP | 经你填入的本地 HTTP 代理分别访问两个出口服务 | 浏览器 IP 正确不能证明此入口正确 |
| 默认通道 TCP | 不读取 HTTP 代理环境变量，通过系统路由查询出口 | 默认通道相同不代表每个应用规则相同 |
| 目标服务 | 无登录凭据的 TLS 请求；记录传输、HTTP 状态与时间 | 401 / 403 或收到响应不等于账号可用 |
| 实际 Claude 连接 | 启动后在当前代理内核的连接列表核对进程、域名、规则、节点 | 只测 ipinfo / Cloudflare 不能证明 Claude 域名也走同一路径 |
| 主备入口 | 手动分别选择 REALITY 和 TLS，重复出口、目标传输及 UDP 测试 | 主备名称相同不代表最终 IP 相同 |
| UDP / STUN | 向多个不同网络的 STUN 目标发包；比较返回的公网地址 | 超时不等于安全；一个端口通过不等于所有 WebRTC 通过 |
| IPv6 | 独立 IPv6 目标、默认路由和连接记录；验证转入预期出口或被阻断 | IPv4 正确、某个 IPv6 目标超时，都不能证明没有 IPv6 旁路 |
| DNS | 使用可关联的随机查询，核对客户端配置、上游连接及权威端看到的递归来源 | fake-IP、DoH 可连、解析器不在某国都不是完整防泄漏证据 |

DNS 若没有可审计的权威端日志或等价证据，写“未验证完整上游路径”。公开测试站会看到你的测试请求，使用前阅读其说明；本项目不把第三方风险分数当账号安全结论。

## 两种不同的“停止”

**启动门禁**：检测失败或关键证据缺失时，新工作台不通过自己的按钮启动 Claude。它不阻止你从其他快捷方式手动启动，也不管已经运行的 Claude。

**网络阻断**：代理、TUN 或住宅上游故障后，受保护流量不能回退本机或 VPS 直连。它依靠正确的路由和按平台实施的防火墙策略。上游进程守护有轮询间隔，杀进程不能当作零窗口的网络阻断。

## 故障演练

先保存工作并退出 Claude，用无账号凭据的测试连接进行演练。记录测试前配置和恢复方法。

1. 住宅出站故障：临时停用住宅连接或使用测试配置令它不可达。受保护请求应失败，不能显示 VPS 机房 IP。
2. 主入口故障：只停用 REALITY 测试入口，检查 TLS 备用入口仍到**相同住宅 IP**。
3. 本机代理退出：确认受保护流量不会直接连接目标；新工作台应拒绝启动。
4. TUN 关闭 / 网卡切换：再次测试默认通道、IPv6 与 DNS。Wi-Fi、网线、热点切换后重新验收。
5. 恢复原配置：核对运行时规则、主备出口和证书，再恢复正常使用。

如果没有配置网络层阻断，明确记录这个缺口。不要通过勾掉警告或修改报告，把尚未做过的演练写成通过。
